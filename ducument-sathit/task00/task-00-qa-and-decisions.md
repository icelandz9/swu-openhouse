## 💬 รายการคำถาม-คำตอบแยกตามมิติ (Dimensional Q&A Transcript)

### 🔹 มิติที่ 1: การเทรนโมเดล AI vs ความเสถียรหน้างานจริง
* **คำถาม**: โจทย์เรื่อง 'การเทรนโมเดล Keypoint Detection' มีข้อกำหนดว่าต้องเทรนโมเดลเอง (Train from scratch / Fine-tune เพื่อส่งงาน/วิจัย) หรือเน้นความเสถียรหน้างานจริงเป็นหลัก?
* **คำตอบจากผู้ใช้**: `เน้นหน้างานจริง`
* **ผลการตัดสินใจทางวิศวกรรม (ADR-01)**:
  * เลือกใช้ **Google MediaPipe Hand Landmarker** (`@mediapipe/tasks-vision`) รันบน WebGL ของเบราว์เซอร์โดยตรง (Client-side 60 FPS)
  * ตัดปัญหาความซับซ้อนในการตั้ง Python/PyTorch Backend Server, ไม่มีความเสี่ยงเรื่องโมเดลแครช หรือความหน่วงในการส่งภาพผ่านเน็ตเวิร์ก

### 🔹 มิติที่ 2: สถาปัตยกรรมระบบ (Next.js vs Go)
* **คำถาม**: สถาปัตยกรรมตัวแอปพลิเคชันหน้าตู้บูท ควรพัฒนาในรูปแบบใด และเปรียบเทียบระหว่าง Next.js กับ Go?
* **คำตอบจากผู้ใช้**: `เลือก Next.js แต่ให้ทำตารางเปรียบเทียบกับ Go อย่างละเอียด`
* **ผลการตัดสินใจทางวิศวกรรม (ADR-04)**:
  * เลือก **Next.js Full-Stack (TypeScript Monorepo)** เพราะสามารถรวบรวมหน้าตู้ (`/booth`), หน้าโหลดรูปมือถือ (`/p/[code]`), หน้าค้นหา (`/find`) และ API ไว้ในที่เดียว
  * กล้องและการประมวลผล Canvas ทำงานบน Web API และ WebGL ได้อย่างเป็นธรรมชาติ ต่างจาก Go ที่ไม่มี Official MediaPipe SDK และต้องติดตั้ง C++ OpenCV Runtime เพิ่มเติมบน Windows

### 🔹 มิติที่ 3: Flow การเลือกฟิลเตอร์และกรอบ เพื่อแก้ปัญหาคอขวดคิวตู้เดี่ยว
* **คำถาม**: ขั้นตอนการเลือกฟิลเตอร์และเทมเพลต เพื่อไม่ให้เกิดคอขวดคนต่อคิวยาวที่หน้าบูทเดี่ยว ควรเป็นรูปแบบใด?
* **คำตอบจากผู้ใช้**: `Hybrid: หน้าตู้เลือกแตะด่วน 10-15 วิ (หรือข้ามได้) แล้วถ้าอยากแต่งเพิ่ม/เปลี่ยนกรอบ สแกน QR ไปทำต่อบนมือถือตัวเอง (คิวตู้ไหลเร็วมาก)`
* **ผลการตัดสินใจทางวิศวกรรม (ADR-02)**:
  * ผู้ใช้งานใช้เวลาหน้าตู้เฉลี่ยเพียง **30–45 วินาทีต่อคน** (รองรับได้ 60–80 คน/ชม.)
  * หน้าตู้มีพรีเซ็ตด่วน 3–4 แบบ หรือกดข้ามไปโชว์ QR ทันที จากนั้นนำภาพไปเปิดบน Mobile Web เพื่อสลับฟิลเตอร์และเปลี่ยนกรอบลายคณะต่อได้อย่างอิสระโดยไม่ขวางคิว

### 🔹 มิติที่ 4: การจัดเก็บภาพ การรับมือเน็ตหลุด และการดึงรูปย้อนหลัง
* **คำถาม**: การรับมือเน็ตหลุด/อืดในงาน และการดึงรูปย้อนหลัง ควรใช้สถาปัตยกรรมแบบใด?
* **คำตอบจากผู้ใช้**: `ใช้แนวทาง Local-First + Short Code 6 หลัก + คลาวด์เก็บ 7 วัน ตามมาตรฐาน PDPA`
* **ผลการตัดสินใจทางวิศวกรรม (ADR-03)**:
  * สร้างรหัสสั้น 6 หลัก เช่น `SWU-DALP` ควบคู่กับ QR Code
  * หน้าจอแสดงข้อความให้น้องถ่ายรูปหน้าจอเก็บไว้ได้ หากสแกนไม่ทัน สามารถนำรหัสมากรอกที่ `https://<domain>/find` เพื่อดาวน์โหลดภาพย้อนหลังได้ตลอด 7 วัน
  * ตั้งค่าระบบ Cloudflare R2 ให้ลบไฟล์ภาพอัตโนมัติ (Auto-purge) หลังครบ 7 วัน สอดคล้องตาม พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล (PDPA)

---

### 🔹 มิติที่ 5: สเกลจำนวนผู้เข้าร่วมงานและการคำนวณความจุ (Sizing)
* **คำถาม**: สเกลจำนวนผู้เข้าร่วมงานที่คาดการณ์ไว้และจำนวนวันจัดงาน อยู่ที่ประมาณเท่าใด?
* **คำตอบจากผู้ใช้**: `งานเปิดบ้าน 2 วัน: คาดการณ์ผู้ถ่าย ~500-1,000 คน/วัน (รวม 1,000-2,000 รูป, ความจุ ~3-5 GB, จัดเก็บ 7 วัน ฟรี 100% บน Cloudflare R2)`
* **ผลการตัดสินใจทางวิศวกรรม**:
  * คำนวณความจุจัดเก็บภาพรวม 1,000–2,000 รูป (ขนาด 1.5–2.5 MB/รูป) ใช้พื้นที่ประมาณ 3–5 GB
  * รองรับได้ 100% ภายใต้ Free Tier ของ Cloudflare R2 (ฟรี 10 GB แรก และฟรีค่า Egress แบนด์วิธ) ➜ ต้นทุนคลาวด์เป็น **0 บาท**

### 🔹 มิติที่ 6: สื่อส่งมอบภาพถ่าย (Digital-Only vs Physical Print)
* **คำถาม**: ตู้ Photo Booth นี้กำหนดให้เป็นแบบ 'ดิจิทัล 100% (สแกนรับไฟล์ผ่าน QR)' หรือ 'มีเครื่องปริ้นต์รูปจริงหน้างานด้วย'?
* **คำตอบจากผู้ใช้**: `Digital-Only 100% (ประหยัดงบสุด คิวไวสุด): เน้นดาวน์โหลดผ่าน QR Code และแชร์ลง Social Media ได้ทันที ต้นทุนหมึก/กระดาษเป็น 0 บาท`
* **ผลการตัดสินใจทางวิศวกรรม (ADR-05)**:
  * ไม่ต้องจัดหาเครื่องพิมพ์ Dye-Sub และไม่ต้องซื้อกระดาษ/หมึกพิมพ์ (งบประมาณ = 0 บาท)
  * ลดเวลาการรอคอยพิมพ์รูป 45–60 วินาทีต่อคน ทำให้ระบายคิวได้รวดเร็วทันทีหลังสแกน QR

### 🔹 มิติที่ 7: รูปแบบภาพถ่าย (Single Shot vs Photostrip) & Reminder Flag
* **คำถาม**: สไตล์ภาพถ่ายที่ตู้จะบันทึกและเรนเดอร์ลงใน Canvas Template จะเป็นรูปแบบใด?
* **คำตอบจากผู้ใช้**: `ตอนนี้ให้ได้ 2 โหมดไปก่อน อาจมีการปรับเปลี่ยนแพลนในอนาคต มาร์กไว้ให้ปรับได้ด้วย แต่ถ้าไม่กลับมาปรับให้เตือน`
* **ผลการตัดสินใจทางวิศวกรรม (ADR-06)**:
  * ออกแบบเอนจิน Canvas ให้รองรับ **Dual-Mode** (โหมด Single Shot 9:16 และโหมด Photostrip 3–4 ช็อตแนวตั้ง)
  * ควบคุมการเปิด-ปิดโหมดผ่าน Configuration Flag
  * ⚠️ **REMINDER FLAG**: มีการบันทึก Flag ในเอกสารว่า ก่อนวันติดตั้งจริงหน้างาน หากทีมงานยังไม่ได้เคาะโหมดหลัก ระบบจะแสดงการแจ้งเตือนให้ตัดสินใจอีกครั้ง

### 🔹 มิติที่ 8: การคัดกรองท่ามือในงานคนเยอะ (Multi-person & Edge Cases)
* **คำถาม**: กรณีมีเพื่อนมายืนถ่ายด้วยกัน 2-3 คน หรือมีคนเดินผ่านฉากหลังในงาน จะให้ระบบ AI กรองการจับท่ามืออย่างไร เพื่อไม่ให้กล้องกดถ่ายเองโดยไม่ตั้งใจ?
* **คำตอบจากผู้ใช้**: `จับมือที่อยู่ใกล้กล้องที่สุด (Largest Hand Area / Depth) + มีปุ่มแตะถ่ายสำรองบนจอ: กรองคนเดินผ่านข้างหลังออก และมีปุ่ม Tap เผื่อกรณีแสงมืดหรือน้องทำท่าไม่ติด คิวจะได้ไม่สะดุด`
* **ผลการตัดสินใจทางวิศวกรรม (ADR-07)**:
  * คัดกรองเฉพาะมือที่มี Bounding Box Area ใหญ่ที่สุดและมีค่าแกนลึก `z` ใกล้กล้องที่สุด
  * ใส่ปุ่มสำรองบนหน้าจอ Viewfinder ให้แตะถ่ายรูปด้วยนิ้วสัมผัสได้ทันที

### 🔹 มิติที่ 9: ฮาร์ดแวร์กล้องประจำตู้
* **คำถาม**: กล้องที่จะนำมาติดตั้งประจำตู้ Photo Booth จะเป็นประเภทใด?
* **คำตอบจากผู้ใช้**: `External USB Webcam 1080p (เช่น Logitech C920/C922/Brio): เสียบ USB ตรงเข้าคอม เสถียรสูงสุด ไม่ร้อน ไม่ดับ ใช้งานต่อเนื่องได้ทั้งวัน รองรับ WebRTC แท้ 100%`
* **ผลการตัดสินใจทางวิศวกรรม (ADR-08)**:
  * ใช้กล้อง USB Webcam 1080p เสียบตรงเข้าพอร์ต USB รองรับ WebRTC Native ใน Chrome Kiosk Mode ไม่เกิดปัญหาเรื่องความร้อนสะสมหรือแบตเตอรี่หมด

### 🔹 มิติที่ 10: การควบคุมดูแลและแก้ไขปัญหาเฉพาะหน้าของสตาฟ (Staff Admin)
* **คำถาม**: เมื่อตู้ค้าง, ผู้ใช้เดินหนีกลางคัน, หรือสตาฟต้องการตรวจเช็กระบบหน้างาน สตาฟควรมีช่องทางควบคุมแบบใด?
* **คำตอบจากผู้ใช้**: `มี 2 แบบ 1 และ 2 (Hidden Secret Trigger บนหน้าตู้ + Mobile Staff Dashboard /admin)`
* **ผลการตัดสินใจทางวิศวกรรม (ADR-09)**:
  * **On-Kiosk Modal**: แตะโลโก้ มศว มุมซ้ายบน 5 ครั้ง (หรือกด `Ctrl+Shift+A`) เพื่อเปิด Staff Modal ลับสำหรับรีเซ็ตคิว/สลับกล้อง
  * **Remote Dashboard**: มีหน้าเว็บ `/admin` บนมือถือของสตาฟผ่าน Local Network สำหรับมอนิเตอร์จำนวนผู้ถ่ายรูปและสั่งรีเซ็ตหน้าจอจากระยะไกล

### 🔹 มิติที่ 11: การจัดวางจอมอนิเตอร์ทางกายภาพ (Monitor Orientation)
* **คำถาม**: จอมอนิเตอร์ที่หันหาผู้ใช้งานหน้าตู้ จะติดตั้งในลักษณะใด?
* **คำตอบจากผู้ใช้**: `จอแนวนอน 16:9 เต็มจอ ส่วนการออกแบบ layout ไว้ทีหลัง`
* **ผลการตัดสินใจทางวิศวกรรม (ADR-10)**:
  * ติดตั้งจอมอนิเตอร์มาตรฐาน 16:9 แนวนอน โดยการจัดวาง Viewfinder และส่วนแสดงผลจะถูกออกแบบใน Task การดีไซน์ Layout (Task 04)
