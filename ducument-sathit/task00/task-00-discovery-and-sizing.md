# Task 00: สรุปผลการตีโจทย์ สถาปัตยกรรมระบบ และประเมินราคา (Discovery & Sizing)
**โครงการ**: SWU Open House - AI Photo Booth  
**เวอร์ชัน**: 2.0 (Deep-Dived via `/grill-me` All Dimensions Locked)  
**วันที่**: 7 พฤศจิกายน 2026  

---

## 1. บทนำและภาพรวมโครงการ (Executive Summary)

โครงการ **SWU Open House Photo Booth** มีเป้าหมายในการสร้างตู้ถ่ายภาพอัจฉริยะ (AI Touchless Photo Booth) ในงานเปิดบ้าน มศว เพื่อดึงดูดผู้ร่วมงานจำนวนมาก โดยเน้น **ความเสถียรหน้างานจริง (Production Stability 100%)**, การระบายคิวที่รวดเร็ว (High Throughput 60–80 คน/ชม.), และการใช้ทรัพยากรที่คุ้มค่าสูงสุด (งบประมาณระบบคลาวด์ 0 บาท)

---

## 2. บันทึกมติสถาปัตยกรรมครบทุกมิติ (Comprehensive ADRs)

### 🎯 ADR-01: AI Keypoint Detection Engine
* **มติ**: ใช้ **Google MediaPipe Hand Landmarker** (`@mediapipe/tasks-vision`) รันบน WebGL ของเบราว์เซอร์โดยตรง ลื่นไหลที่ **60 FPS**
* **เหตุผล**: มีโมเดล Landmark 21 จุดพร้อมใช้ ไม่ต้องเสียเวลาเทรนโมเดลใหม่ ไม่มีความเสี่ยงเรื่องแครชหน้างาน และไม่ต้องตั้ง Python Backend

### ⚡ ADR-02: Flow การเลือกฟิลเตอร์และเทมเพลต (Queue Optimization)
* **มติ**: **Hybrid Architecture (ตู้เร็ว + แต่งต่อบนมือถือ)**
* **รายละเอียด**: หน้าตู้มีพรีเซ็ตด่วน 10–15 วินาที หรือกดข้ามไปโชว์ QR Code ทันที จากนั้นน้องสแกน QR ไปสลับฟิลเตอร์และเปลี่ยนกรอบลายคณะต่างๆ ต่อบนมือถือตัวเอง ทำให้ตู้ใช้เวลาเฉลี่ยเพียง **30–45 วินาทีต่อคน**

### 🛡️ ADR-03: Storage Strategy & สิทธิ์การดึงรูปย้อนหลัง (PDPA Compliant)
* **มติ**: **Short Code 6 ตัวอักษร (`OPH-XXXX`) แสดงบนมือถือ + หน้าตู้แสดงเฉพาะ QR Code สะอาดตา + คลาวด์จัดเก็บ 7 วัน**
* **รายละเอียด**: หน้าตู้ Kiosk แสดงเฉพาะ QR Code ขนาดใหญ่ให้สแกนทันที (ไม่แสดงรหัสตัวอักษรบนหน้าตู้) เมื่อสแกนเข้าสู่มือถือแล้ว รหัส `OPH-XXXX` จะปรากฏที่หัวเว็บมือถือเพื่อให้น้องจดหรือบันทึกเก็บไว้ดึงรูปย้อนหลังผ่านหน้า `https://<domain>/find` ได้ตลอด 7 วัน โดยหากน้องสแกนหน้าตู้ไม่ทัน ก็สามารถเดินมาขอ QR Code ย้อนหลังกับพี่สตาฟที่บูทผ่านหน้า `/admin` ได้ ระบบจะ Auto-purge ไฟล์ทิ้งอัตโนมัติเมื่อครบ 7 วันตามมาตรฐาน PDPA

### ⚖️ ADR-04: กรอบเทคโนโลยีของระบบ (Technology Stack)
* **มติ**: **Next.js Full-Stack (TypeScript Monorepo)**
* **เหตุผล**: รวมหน้าตู้ (`/booth`), หน้าดาวน์โหลดมือถือ (`/p/[code]`), หน้าค้นหา (`/find`), หน้าแดชบอร์ดสตาฟ (`/admin`) และ API ไว้ในโปรเจกต์เดียว รันบน Chrome Kiosk Mode ได้ทันที

### 🖨️ ADR-05: สื่อส่งมอบภาพถ่าย (Digital-Only vs Physical Print)
* **มติ**: **Digital-Only 100% (ไม่มีเครื่องพิมพ์ภาพถ่าย)**
* **เหตุผล**:
  * ลดต้นทุนค่ากระดาษและหมึกพิมพ์เป็น **0 บาท**
  * ลดเวลาการรอคอยหน้าตู้ ไม่ต้องยืนรอเครื่องพิมพ์ 45–60 วินาที คิวระบายได้รวดเร็วสูงสุด
  * ตอบโจทย์เยาวชนที่ต้องการภาพดิจิทัลไปแชร์ลง Instagram Story / TikTok ทันที

### 🖼️ ADR-06: รูปแบบภาพถ่าย (Photo Layout Modes) & Reminder Flag
* **มติ**: **รองรับทั้ง 2 โหมด (Dual-Mode Architecture: Single Shot 9:16 และ Photostrip 3–4 ช็อต)**
* **การตั้งค่า**: ควบคุมผ่าน Configuration (`boothConfig.supportedModes = ['single', 'photostrip']`)
* ⚠️ **REMINDER FLAG (แจ้งเตือน)**: บันทึกมาร์กไว้ว่าระบบเปิดให้ปรับเปลี่ยนสลับโหมดได้ในอนาคต หากทีมงานไม่ได้กลับมาสรุปเจาะจงก่อนวันงานจริง ระบบจะแจ้งเตือนให้เคาะโหมดหลักก่อนเริ่มงาน

### 👥 ADR-07: การคัดกรองท่ามือในงานคนเยอะ (Multi-person & Edge Case Filtering)
* **มติ**: **จับเฉพาะมือที่อยู่ใกล้กล้องที่สุด (Largest Hand Area & Closest Depth `z`) + ปุ่ม Tap บนจอ**
* **รายละเอียด**:
  * คำนวณ Bounding Box Area และความลึกของข้อมือ Landmark เพื่อคัดกรองคนเดินผ่านฉากหลังออก
  * มีปุ่มจำลองบนหน้าจอ "แตะเพื่อถ่ายรูป (Tap to capture)" รองรับกรณีแสงไฟในฮอลล์มืด หรือผู้ใช้งานไม่สะดวกทำท่ามือ

### 📷 ADR-08: ฮาร์ดแวร์กล้องและการเชื่อมต่อ
* **มติ**: **External USB Webcam Full HD 1080p (เช่น Logitech C920 / C922 / Brio)**
* **เหตุผล**: เสียบสาย USB ตรงเข้าคอมพิวเตอร์ รองรับมาตรฐาน WebRTC Native ไม่เกิดปัญหาความร้อนสะสมหรือแบตเตอรี่เสื่อมสภาพเมื่อเปิดใช้งานต่อเนื่อง 6–8 ชั่วโมงในวันงาน

### 🛠️ ADR-09: ระบบควบคุมและการกู้คืนของสตาฟ (Dual Staff Admin Controls)
* **มติ**: **มีระบบควบคุม 2 รูปแบบคู่ขนาน**
  1. **Hidden Secret Trigger บนหน้าตู้**: แตะโลโก้ มศว มุมซ้ายบน 5 ครั้ง หรือกดปุ่มลัด `Ctrl + Shift + A` เพื่อเปิด Staff Modal (รีเซ็ตคิว, สลับกล้อง, ตรวจสอบสถานะการเชื่อมต่อ)
  2. **Remote Mobile Staff Dashboard (`/admin`)**: สตาฟสามารถเปิดหน้าเว็บแดชบอร์ดบนสมาร์ตโฟนผ่าน Local Network เพื่อดูยอดผู้ถ่ายรูป real-time และสั่งรีเซ็ตหน้าจอจากระยะไกลได้

### 🖥️ ADR-10: การจัดวางจอมอนิเตอร์ทางกายภาพ (Monitor Orientation)
* **มติ**: **จอมอนิเตอร์แนวนอน 16:9 แบบเต็มจอ (Landscape Full Screen)**
* **รายละเอียด**: ติดตั้งมอนิเตอร์มาตรฐาน 16:9 แนวนอน โดยการออกแบบ Grid Layout ภายในหน้าจอจะถูกจัดสรรใน Task ถัดไป

## 3. ข้อมูลจำเพาะความต้องการเชิงวิศวกรรม (Engineering Requirements)

### 3.1 Functional Requirements (FR)
- **FR-01**: สตรีมภาพจากกล้อง USB Webcam ความละเอียด 1080p ผ่าน WebRTC
- **FR-02**: ประมวลผล MediaPipe Hand Landmarker 21 จุด บน WebGL ที่ความเร็ว 60 FPS
- **FR-03**: คัดกรองจับท่าทางเฉพาะมือที่ใกล้ที่สุด (Largest Bounding Box) พร้อมฟิลเตอร์ตัด Noise
- **FR-04**: กลไกนับถอยหลังอัตโนมัติเมื่อทำท่ามือ Peace Sign หรือ Open Palm ค้าง 1.5 วินาที
- **FR-05**: ปุ่มกดฉุกเฉินบนหน้าจอ (Touch / Click Fallback) เพื่อสั่งถ่ายภาพได้ทันที
- **FR-06**: การสลับโหมดถ่ายภาพระหว่าง Single Shot (1 ภาพ) และ Photostrip (3–4 ช็อต)
- **FR-07**: เอนจิน Canvas Compositor ผสานเลเยอร์ภาพถ่าย + ฟิลเตอร์สี + กรอบ PNG มศว
- **FR-08**: การออกรหัสสั้น `OPH-XXXX` และสร้าง QR Code ลิงก์ตรงสู่หน้ารูปภาพ (หน้าตู้แสดงเฉพาะ QR Code)
- **FR-09**: หน้าเว็บมือถือสำหรับเปิดดูภาพความละเอียดสูง สลับฟิลเตอร์ และดาวน์โหลด
- **FR-10**: หน้าเว็บ `/find` สำหรับกรอกรหัส 6 หลักเพื่อดึงรูปย้อนหลังได้ตลอด 7 วัน
- **FR-11**: Staff Modal บนหน้าตู้ (แตะโลโก้ 5 ครั้ง) และ Staff Web Dashboard (`/admin`)

### 3.2 Non-Functional Requirements (NFR)
- **NFR-01 (Inference Speed)**: MediaPipe Gesture Recognition >= 30–60 FPS
- **NFR-02 (Session Latency)**: เวลาประมวลผลตั้งแต่ถ่ายเสร็จจนแสดง QR Code < 1.0 วินาที
- **NFR-03 (Booth Throughput)**: เวลาเฉลี่ยต่อคนหน้าตู้ 30–45 วินาที (รองรับ 60–80 คน/ชม.)
- **NFR-04 (Offline Resilience)**: บันทึกรูปลงเครื่องตู้ทันทีก่อนอัปโหลด แม้เน็ตหลุดตู้ก็ไม่ค้าง
- **NFR-05 (PDPA Compliance)**: กำหนดอายุไฟล์ภาพ 7 วัน และลบทำลายทิ้งอัตโนมัติ
- **NFR-06 (Cost Cap)**: ต้นทุนค่าบริการคลาวด์และฮาร์ดแวร์เพิ่มเติม = 0 บาท
