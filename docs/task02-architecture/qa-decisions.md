### คำถามที่ 1: การจัดการ State Machine และ Timeout หน้าจอ (FSM State Transition & Failure Recovery)
* **คำถาม**: [Task 02 - State Machine & Failure Recovery] ในการออกแบบ Finite State Machine (FSM) ของหน้าจอตู้ Kiosk หากเกิดกรณีผู้ใช้ชักมือกลับกะทันหัน หรือเดินหนีไประหว่างกระบวนการถ่ายรูป คุณต้องการให้ระบบจัดการ State Transition อย่างไรครับ?
* **ตัวเลือกที่มีให้เลือก**:
  1. *(Recommended)* Auto-Cancel & Smart Reset: ถ้าน้องชักมือกลับหรือเดินหนีระหว่างนับถอยหลัง ให้ยกเลิกและรีเซ็ตกลับหน้า Idle ทันที ส่วนหน้า Preview มีเวลานับถอยหลัง 8 วิ หากไม่กดถ่ายใหม่ ให้เปลี่ยนไปหน้า QR Code อัตโนมัติ
  2. Hard Trigger: เมื่อนับถอยหลังเริ่มแล้ว ต้องถ่ายให้จบเสมอแม้จะชักมือกลับ แล้วไปวัดดวงที่หน้า Preview เอาเองว่าจะกดถ่ายใหม่หรือไม่
  3. Strict Mode: ต้องรอให้น้องหรือสตาฟกดปุ่มบนหน้าจอเท่านั้น หากไม่มีคนกด ให้ค้างหน้านั้นไว้ไม่รีเซ็ตอัตโนมัติ
* **คำตอบที่เลือก**: `แบบที่ 1 แต่หน้า preview เพิ่มเป็น 10 วิ`
* **มติทางวิศวกรรม**:
  * เมื่อผู้ใช้ชักมือกลับระหว่างนับถอยหลัง ระบบจะยกเลิกการถ่ายทันทีและกลับสู่สถานะ `IDLE`
  * หน้าจอแสดงผล Preview ภาพถ่าย ปรับเวลานับถอยหลังเป็น **10 วินาที** (จากเดิม 8 วิ) หากไม่กดถ่ายใหม่ ระบบจะเปลี่ยนผ่านเข้าสู่หน้าจอแสดง QR Code โดยอัตโนมัติ

### คำถามที่ 2: สถาปัตยกรรมแคชไฟล์และการอัปโหลดเมื่อเน็ตหลุด (Offline Storage & Local Caching)
* **คำถาม**: [Task 02 - Offline Storage & Local Caching Architecture] เมื่อตู้ถ่ายรูปบันทึกภาพความละเอียดสูง 1080p ในจังหวะที่สัญญาณอินเทอร์เน็ตในงานขัดข้อง สถาปัตยกรรมการจัดเก็บไฟล์ภาพชั่วคราวในเครื่องตู้ Kiosk ควรเป็นรูปแบบใดครับ?
* **ตัวเลือกที่มีให้เลือก**:
  1. *(Recommended)* Next.js Local API Route บันทึกลง Disk ในเครื่องตู้ตรงๆ (Local SSD) + Background Sync Worker: เมื่อถ่ายเสร็จส่ง POST เข้า localhost บันทึกไฟล์ลงฮาร์ดดิสก์ตู้ทันที 100% ปลอดภัยจากอาการแรมล้น และมี Worker คอยซิงค์ขึ้น Cloudflare R2 เมื่อเชื่อมต่ออินเทอร์เน็ตได้
  2. Browser IndexedDB (จัดเก็บใน Local Storage ของ Chrome): เก็บข้อมูลแบบ Blob ในฐานข้อมูลเบราว์เซอร์ ข้อดีคือไม่ต้องเขียนไฟล์ลง Disk แต่หากเบราว์เซอร์แครชหรือมีปัญหาอาจกู้ไฟล์ยากกว่า
  3. Memory-Only (เก็บชั่วคราวใน RAM): ไม่บันทึกลงไดรฟ์ พยายามส่งขึ้น Cloudflare R2 ทันที หากเน็ตหลุดและตู้ดับภาพจะสูญหาย
* **คำตอบที่เลือก**: `ให้รอสัญญาณมาได้ไหมแล้วทำงาน process นั้นต่อ`
* **มติทางวิศวกรรม**:
  * บันทึกภาพลง Local Cache/SSD ของเครื่องตู้ทันที และเข้าสู่กระบวนการตรวจสอบสัญญาณเน็ตเวิร์ก

### คำถามที่ 3: พฤติกรรมหน้าตู้เมื่อรอสัญญาณเน็ต (Network Resilience & Queue Continuity)
* **คำถาม**: [Task 02 - Network Resilience & Queue Continuity] สำหรับกรณี 'รอสัญญาณเน็ตมาแล้วทำงาน process นั้นต่อ' คุณต้องการให้ประสบการณ์หน้าตู้ Kiosk ในจังหวะที่เน็ตหลุดทำงานแบบใดครับ?
* **ตัวเลือกที่มีให้เลือก**:
  1. *(Recommended)* ตู้ไม่อั้นคิว (Background Resume): บันทึกรูปลงเครื่องตู้ทันทีและออก QR Code ให้น้องสแกนได้เลย ส่วนขั้นตอนอัปโหลดขึ้น Cloudflare R2 จะตั้งสถานะ Pending รอจนกว่าสัญญาณเน็ตจะกลับมา แล้วระบบจะ Resume ทำงานต่ออัตโนมัติเบื้องหลัง คิวหน้าตู้จึงไหลลื่นไม่สะดุด
  2. หน้าตู้หยุดรอเน็ต (Blocking Mode): เมื่อถ่ายเสร็จ หากเน็ตหลุด ให้หน้าตู้แสดงสถานะ 'กำลังรอสัญญาณอินเทอร์เน็ต...' ค้างไว้จนกว่าเน็ตจะกลับมา อัปโหลดเสร็จแล้วจึงจะโชว์ QR Code (ข้อควรระวัง: หากเน็ตดับ 2-3 นาที คิวหน้าตู้จะหยุดชะงัก)
* **คำตอบที่เลือก**: `หน้าตู้หยุดรอเน็ต (Blocking Mode): เมื่อถ่ายเสร็จ หากเน็ตหลุด ให้หน้าตู้แสดงสถานะ 'กำลังรอสัญญาณอินเทอร์เน็ต...' ค้างไว้จนกว่าเน็ตจะกลับมา อัปโหลดเสร็จแล้วจึงจะโชว์ QR Code (ข้อควรระวัง: หากเน็ตดับ 2-3 นาที คิวหน้าตู้จะหยุดชะงัก)`
* **มติทางวิศวกรรม**:
  * ใช้ **Blocking Upload Architecture**: เมื่อถ่ายภาพเสร็จ ระบบจะตรวจสอบสถานะเครือข่ายก่อน หากไม่มีสัญญาณอินเทอร์เน็ต หน้าตู้จะขึ้นสถานะ `WAITING_NETWORK` พร้อมข้อความ "กำลังรอสัญญาณอินเทอร์เน็ต..." เพื่อรอให้อัปโหลดไฟล์ขึ้น Cloudflare R2 สำเร็จก่อน จึงจะสร้างและแสดง QR Code

### คำถามที่ 4: เอนจินการประมวลผลแต่งสีและใส่กรอบรูป (Image Compositing Engine)
* **คำถาม**: [Task 02 - Image Compositing Architecture] ในขั้นตอนการแต่งสีภาพ (6 พรีเซ็ต + แถบความสว่าง) และการใส่กรอบเทมเพลต มศว 3 แบบบนมือถือน้อง สถาปัตยกรรมเอนจินการประมวลผลภาพ (Compositing Engine) ควรทำงานที่ฝั่งใดครับ?
* **ตัวเลือกที่มีให้เลือก**:
  1. *(Recommended)* Client-Side Canvas 2D บนมือถือน้อง 100%: ประมวลผลปรับสีและผสานกรอบ PNG ด้วย HTML5 Canvas บนเบราว์เซอร์มือถือน้องโดยตรง ข้อดีคือเห็นผลลัพธ์พรีวิวทันทีแบบเรียลไทม์ ปรับแสงได้ลื่นไหล ไม่เปลือง CPU เซิร์ฟเวอร์ และไม่มีค่าใช้จ่ายคลาวด์ (0 บาท)
  2. Server-Side Rendering (Node.js Sharp / ImageMagick บน Cloud): ส่งค่าพารามิเตอร์สีและรหัสกรอบไปให้เซิร์ฟเวอร์เรนเดอร์ภาพใหม่แล้วส่งกลับมา ข้อดีคือควบคุมคุณภาพไฟล์ได้แน่นอน แต่ข้อเสียคือมี Network Latency ทุกครั้งที่เปลี่ยนฟิลเตอร์ และเปลือง Server Compute
  3. Hybrid (พรีวิวบนมือถือ + เรนเดอร์ไฟล์จริงบนเซิร์ฟเวอร์): ให้มือถือพรีวิวคร่าวๆ แต่ตอนกดดาวน์โหลดจะสั่งเซิร์ฟเวอร์ประกอบภาพความละเอียดสูง 300 DPI
* **คำตอบที่เลือก**: `(Recommended) Client-Side Canvas 2D บนมือถือน้อง 100%: ประมวลผลปรับสีและผสานกรอบ PNG ด้วย HTML5 Canvas บนเบราว์เซอร์มือถือน้องโดยตรง ข้อดีคือเห็นผลลัพธ์พรีวิวทันทีแบบเรียลไทม์ ปรับแสงได้ลื่นไหล ไม่เปลือง CPU เซิร์ฟเวอร์ และไม่มีค่าใช้จ่ายคลาวด์ (0 บาท)`
* **มติทางวิศวกรรม**:
  * ใช้ HTML5 Canvas 2D Context ประมวลผลบนเครื่องสมาร์ตโฟนของผู้ใช้ 100% สลับพรีเซ็ตและปรับความสว่างแบบ Real-time โดยไม่ส่งคำขอประมวลผลไปยังเซิร์ฟเวอร์ (Zero Cloud Compute Spend)

### คำถามที่ 5: สถาปัตยกรรมระบบหลังบ้านสตาฟและการดูภาพย้อนหลัง (Staff Back-Office Architecture)
* **คำถาม**: [Task 02 - Staff Back-Office Architecture] ระบบหลังบ้านสำหรับสตาฟ (/admin) ที่ใช้เปิดดู Timeline รูปถ่ายล่าสุดเพื่อออก QR Code ย้อนหลังให้น้อง สถาปัตยกรรมการดึงและจัดการข้อมูล (Data Retrieval Architecture) ควรเป็นรูปแบบใดครับ?
* **ตัวเลือกที่มีให้เลือก**:
  1. *(Recommended)* Serverless Metadata Store (Cloudflare KV หรือ Upstash Redis ฟรี): เมื่อถ่ายรูปเสร็จ ตู้จะบันทึกรหัส OPH-XXXX, เวลาถ่าย, และ URL รูปไว้ใน Key-Value Store หน้าสตาฟ /admin จะดึงรายการล่าสุด 50 รูปมาเรียงตามเวลาได้ทันทีในระดับมิลลิวินาที ค้นหาและเปิด QR ได้รวดเร็วที่สุด
  2. Direct R2 Bucket Listing (ดึงรายการไฟล์ตรงจาก Cloudflare R2 โดยไม่ต้องมีฐานข้อมูล): สตาฟเปิดดูรูปโดยให้เซิร์ฟเวอร์ไปอ่านรายชื่อไฟล์ใน R2 Bucket ตามเวลา LastModified ข้อดีคือไม่ต้องมี Database เพิ่มเติม แต่การโหลดแกลเลอรีอาจช้ากว่าเล็กน้อยเมื่อมีรูปเป็นพันใบ
  3. Local P2P / Local Network (สตาฟดึงรูปตรงจากคอมพิวเตอร์ตู้ผ่าน Wi-Fi เดียวกัน): เหมาะกับกรณีไม่มีเน็ตออกข้างนอก แต่มีข้อจำกัดคือมือถือสตาฟต้องเกาะ Wi-Fi ตัวเดียวกันกับคอมตู้ตลอดเวลา
* **คำตอบที่เลือก**: `เพิ่มเป็นดูรูป ทั้งหมดได้ไหมแบบที่ 1`
* **มติทางวิศวกรรม**:
  * ใช้ Serverless Metadata Store จัดเก็บประวัติภาพถ่ายทุกใบ พร้อมจัดทำหน้าแดชบอร์ดสตาฟ `/admin` ให้มีโหมด **"ดูรูปทั้งหมด (View All Photos)"** รองรับการเลื่อนดูแบบ Pagination / Infinite Scroll และมีตัวกรองค้นหาตามเวลา (Timestamp Filter) และค้นหาตามรหัส `OPH-XXXX`

### คำถามที่ 6: การติดตั้งฮาร์ดแวร์กล้องและการจัดสัดส่วนภาพ (Camera Resolution & Physical Mount)
* **คำถาม**: [Task 02 - Camera Resolution & Physical Mount Strategy] เนื่องจากมอนิเตอร์เป็นแนวนอน 16:9 แต่ภาพถ่ายของผู้ใช้เป็นแนวตั้ง 9:16 กล้อง USB Webcam 1080p หน้าตู้จะถูกติดตั้งในลักษณะใดทางกายภาพครับ?
* **ตัวเลือกที่มีให้เลือก**:
  1. *(Recommended)* กล้องติดตั้งแนวนอนปกติ (Standard Landscape) + ซอฟต์แวร์ตัดส่วนแนวตั้งตรงกลาง (Center Crop 9:16): สตาฟติดตั้งง่าย ใช้ขาตั้งกล้องทั่วไปได้เลย หน้าจอ Viewfinder จะมีกรอบไกด์แนวตั้ง 9:16 ให้น้องยืนตรงกลางและตัดขอบข้างออกให้อัตโนมัติ
  2. กล้องติดตั้งหมุนแนวตั้ง 90 องศา (Vertical Portrait Mount): ต้องมีขาจับหมุนกล้องเป็นแนวตั้ง ข้อดีคือได้ความละเอียดแนวตั้งเต็ม 1080x1920 พิกเซล แต่ต้องเซ็ตอัปทางกายภาพเพิ่ม
  3. ให้สตาฟเลือกได้ในการตั้งค่า (Software Orientation Toggle): ในหน้าสตาฟมีตัวเลือกว่าติดตั้งกล้องแบบแนวนอนหรือแนวตั้ง เพื่อปรับการหมุนภาพ (Rotate 0° / 90°) ได้ตามหน้างานจริง
* **คำตอบที่เลือก**: `(Recommended) กล้องติดตั้งแนวนอนปกติ (Standard Landscape) + ซอฟต์แวร์ตัดส่วนแนวตั้งตรงกลาง (Center Crop 9:16): สตาฟติดตั้งง่าย ใช้ขาตั้งกล้องทั่วไปได้เลย หน้าจอ Viewfinder จะมีกรอบไกด์แนวตั้ง 9:16 ให้น้องยืนตรงกลางและตัดขอบข้างออกให้อัตโนมัติ`
* **มติทางวิศวกรรม**:
  * กล้องเว็บแคมติดตั้งในแนวนอนมาตรฐาน (Standard 16:9 1920x1080)
  * หน้าจอ Viewfinder แสดงกรอบไกด์แนวตั้ง 9:16 ตรงกลางจอ และระบบ Canvas Pipeline จะตัดขอบข้างแบบ Center Crop ได้ขนาด 608x1080 พิกเซล (หรือขยายสัดส่วน 9:16) โดยไม่ต้องหมุนกล้องจริง

### คำถามที่ 7: การจัดส่งเทมเพลตกรอบรูปและธีมสาขาวิชา (Frame Template Delivery & CPE Theme)
* **คำถาม**: [Task 02 - Frame Template Asset Delivery] เพื่อให้การเปิดเว็บและการสลับกรอบรูป 3 แบบบนมือถือน้องรวดเร็วที่สุด การจัดเก็บและโหลดไฟล์กรอบเทมเพลต มศว (PNG Alpha Transparent) ควรใช้สถาปัตยกรรมแบบใดครับ?
* **ตัวเลือกที่มีให้เลือก**:

  2. Dynamic Template Catalog (ดึงรายชื่อและไฟล์กรอบผ่าน API /api/templates): เปิดโอกาสให้สตาฟอัปโหลดกรอบใหม่เพิ่มระหว่างวันงานได้ แต่จะมีจังหวะรอโหลด API เล็กน้อยก่อนแสดงผล
* **คำตอบที่เลือก**: `แบบที่ 1 แต่เทมเพลตจะเป็นของ cpe`
* **มติทางวิศวกรรม**:

  * **ธีมของเทมเพลตเป็นของภาควิชาวิศวกรรมคอมพิวเตอร์ (CPE SWU)**:

### คำถามที่ 8: เงื่อนไข Timeout ในจังหวะรอสัญญาณเน็ต (Network Wait Timeout Policy)
* **คำถาม**: [Task 02 - ข้อกำหนด Timeout: จังหวะรอสัญญาณเน็ต (Network Wait Timeout)] ในจังหวะที่หน้าตู้หยุดรอสัญญาณเน็ต (Blocking Mode) เพื่ออัปโหลดรูป คุณต้องการกำหนดเงื่อนไข Timeout ไว้อย่างไรครับ?
* **ตัวเลือกที่มีให้เลือก**:
  1. *(Recommended)* Auto-Retry สูงสุด 30 วินาที + ปุ่มสตาฟปลดล็อก: หากเน็ตหลุด ให้พยายามเชื่อมต่อใหม่แบบอัตโนมัติ 30 วินาที หากยังไม่ติด ให้ขึ้นปุ่ม 'แจ้งสตาฟ (Staff PIN)' เพื่อให้สตาฟเข้ามาดูระบบหรือข้ามขั้นตอนนี้ได้ ไม่ให้ตู้ค้างถาวร
  2. รอเน็ตไม่จำกัดเวลา (Infinite Wait): ให้หน้าจอหมุนรอจนกว่าสัญญาณเน็ตจะกลับมาจริง 100% ไม่จำกัดเวลา (สอดคล้องกับมติ Blocking Mode)
  3. รอเน็ตสั้น 15 วินาที: หากรอเกิน 15 วินาทีแล้วเน็ตยังไม่มา ให้บันทึกรูปไว้ในเครื่องตู้แล้วข้ามไปหน้า QR Code ทันทีเพื่อปล่อยคิว
* **คำตอบที่เลือก**: `แบบที่ 2 แต่มีการแจ้ง staff มากดได้`
* **มติทางวิศวกรรม**:
  * หน้าตู้จะรอสัญญาณเน็ตแบบต่อเนื่อง (Infinite Retry Loop) พร้อมแอนิเมชันสถานะกำลังเชื่อมต่อ
  * มีการแสดงปุ่มแจ้งเตือนหรือเปิดให้สตาฟกดปุ่มปลดล็อกด้วย **Staff PIN** เพื่อเข้าไปตรวจสอบสถานะเน็ต หรือสั่งรีเซ็ตข้ามขั้นตอนได้ในกรณีที่เน็ตหน้างานดับยาว

### คำถามที่ 9: แอนิเมชันแฟลชและจังหวะบันทึกภาพ (Flash Animation & Capture Trigger)
* **คำถาม**: [Task 02 - ข้อกำหนด Animation แฟลช: เอฟเฟกต์จังหวะบันทึกภาพ] ในจังหวะที่นับถอยหลัง 3.. 2.. 1.. สิ้นสุดและบันทึกภาพ คุณต้องการให้แอนิเมชันแฟลชและเอฟเฟกต์หน้าจอเป็นรูปแบบใดครับ?
* **คำตอบที่เลือก**: `จับการแบมือทำท่า 1.5วิ นับถอยหลังเป็นตัวเลข 3 2 1 แล้วจอจะสว่างวาบสีขาว`
* **มติทางวิศวกรรม**:
  * **เงื่อนไข Trigger**: ทำท่าแบมือ 5 นิ้ว (Open Palm) ค้างต่อเนื่อง **1.5 วินาที**
  * **Visual Countdown**: แสดงตัวเลขนับถอยหลังขนาดใหญ่ **3.. 2.. 1..** ซ้อนทับบนภาพกล้อง
  * **Flash Effect**: เมื่อนับถึง 0 หน้าจอจะแสดง **White Flash Overlay (สว่างวาบสีขาวเต็มหน้าจอ 150ms)** พร้อมบันทึกภาพความละเอียดสูงทันที
