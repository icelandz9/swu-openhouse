### คำถามที่ 1: การเทรนโมเดล Keypoint Detection
* **คำถาม**: โจทย์เรื่อง 'การเทรนโมเดล Keypoint Detection' มีข้อกำหนดว่าต้องเทรนโมเดลเอง (Train from scratch / Fine-tune เพื่อส่งงาน/วิจัย) หรือเน้นความเสถียรหน้างานจริงเป็นหลักครับ?
* **ตัวเลือกที่มีให้เลือก**:
  1. *(Recommended)* MediaPipe Pre-trained + Rule-based/Tiny MLP (รันบน Browser ตรง 60 FPS, ไม่ต้องตั้ง Python Backend, เสถียรและเร็วที่สุด)
  2. ต้องเทรนโมเดลเองจริงจัง (Custom Model เช่น YOLOv8-pose หรือ PyTorch จากศูนย์ เพื่อส่งอาจารย์/วิจัย - ต้องมี Python + WebSocket)
  3. Hybrid: ใช้ MediaPipe สกัด 21 Keypoints แล้วเทรน Classifier เล็กๆ (MLP/Random Forest) จำแนกท่าทางเฉพาะของ มศว เอง
* **คำตอบที่เลือก**: `เน้นหน้างานจริง` (เลือกแนวทางที่ 1)
* **มติทางวิศวกรรม (ADR-01)**:
  * เลือกใช้ Google MediaPipe Hand Landmarker (`@mediapipe/tasks-vision`) รันบน WebGL ของเบราว์เซอร์โดยตรง (Client-side 60 FPS)
  * ตัดปัญหาความซับซ้อนในการตั้ง Python/PyTorch Backend Server ไม่มีความเสี่ยงเรื่องโมเดลแครช หรือความหน่วงจากเน็ตเวิร์ก

### คำถามที่ 2: ขั้นตอนการเลือกฟิลเตอร์และเทมเพลต (Queue Optimization)
* **คำถาม**: เรื่อง 'ขั้นตอนการเลือกฟิลเตอร์และเทมเพลต' เพื่อไม่ให้เกิดคอขวดคนต่อคิวยาวที่หน้าบูทเดี่ยว คุณต้องการให้ Flow การทำงานเป็นแบบใดครับ?
* **ตัวเลือกที่มีให้เลือก**:
  1. *(Recommended)* Hybrid: หน้าตู้เลือกแตะด่วน 10-15 วิ (หรือข้ามได้) แล้วถ้าอยากแต่งเพิ่ม/เปลี่ยนกรอบ สแกน QR ไปทำต่อบนมือถือตัวเอง (คิวตู้ไหลเร็วมาก)
  2. ทำบนมือถือ 100%: ตู้ทำหน้าที่แค่ถ่ายรูปเสร็จปุ๊บ โชว์ QR ทันที ภายใน 15 วิ แล้วน้องไปเลือกฟิลเตอร์/กรอบบนมือถือเอง (รองรับได้สูงสุด 100+ คน/ชม.)
  3. ทำที่ตู้ 100%: ต้องยืนแต่งรูป เลือกฟิลเตอร์ และกรอบหน้าจอจนเสร็จที่ตู้เท่านั้น (ใช้จอ Touchscreen/เมาส์ คนละ ~2-3 นาที คิวจะยาว)
* **คำตอบที่เลือก**: `(Recommended) Hybrid: หน้าตู้เลือกแตะด่วน 10-15 วิ (หรือข้ามได้) แล้วถ้าอยากแต่งเพิ่ม/เปลี่ยนกรอบ สแกน QR ไปทำต่อบนมือถือตัวเอง (คิวตู้ไหลเร็วมาก)`
* **มติทางวิศวกรรม (ADR-02)**:
  * ผู้ใช้งานใช้เวลาหน้าตู้เฉลี่ยเพียง 20–30 วินาทีต่อคน (รองรับได้ 60–80 คน/ชม.)
  * หน้าตู้ถ่ายภาพเสร็จขึ้น QR ทันที น้องนำไปเปิดแต่งฟิลเตอร์และเปลี่ยนกรอบบนมือถือตัวเองโดยไม่ยืนขวางคิว

### คำถามที่ 3: การรับมือเน็ตหลุดในงานและการดึงรูปย้อนหลัง
* **คำถาม**: เรื่อง 'การรับมือเน็ตหลุด/อืดในงาน' และ 'การดึงรูปย้อนหลัง' คุณต้องการใช้สถาปัตยกรรมแบบใดครับ?
* **ตัวเลือกที่มีให้เลือก**:
  1. *(Recommended)* Local-First + Short Code 6 หลัก + คลาวด์เก็บ 7 วัน: โชว์ QR ทันทีไม่ต้องรอเน็ต, รูปเซฟลงเครื่องก่อนแล้วซิงค์ขึ้นคลาวด์พื้นหลัง, น้องถ่ายรหัสเก็บไว้เข้าเว็บมาย้อนหลังได้ 7 วัน
  2. Local Hotspot (ออฟไลน์ 100% ไม่พึ่งเน็ตมหาลัย): ปล่อย Wi-Fi จากตู้ ให้น้องต่อ Wi-Fi แล้วโหลดจากเครื่องตู้ตรงๆ (ปลอดภัยสุด แต่ต้องให้น้องสลับ Wi-Fi)
  3. คลาวด์ล้วน (Online-only): อัปโหลดขึ้นคลาวด์เสร็จก่อนถึงจะขึ้น QR Code ถ้าน้องปิดแท็บหรือสแกนไม่ทันจะไม่มีรหัสย้อนหลัง
* **คำตอบที่เลือก**: `ข้ามไปถามข้อสุดท้าย` (ต่อมาผู้ใช้ยืนยันใช้ระบบ Local-First + Short Code รหัส `OPH-XXXX` แสดงบนมือถือ + คลาวด์เก็บ 7 วัน ตามมาตรฐาน PDPA)
* **มติทางวิศวกรรม (ADR-03)**:
  * บันทึกภาพลงดิสก์ตู้ทันทีและออก QR ได้แม้ออฟไลน์
  * ใช้รหัส `OPH-XXXX` โดยแสดงที่หัวเว็บมือถือให้น้องจดจำ และมีหน้า `/find` พร้อมระบบลบไฟล์อัตโนมัติเมื่อครบ 7 วัน

### คำถามที่ 4: สถาปัตยกรรมแอปพลิเคชัน (Next.js vs Go)
* **คำถาม**: (ข้อสุดท้าย) สถาปัตยกรรมตัวแอปพลิเคชันหน้าตู้บูท คุณต้องการพัฒนาเป็นรูปแบบใดครับ?
* **ตัวเลือกที่มีให้เลือก**:
  1. *(Recommended)* Next.js Full-Stack (Monorepo): หน้าตู้รันผ่าน Chrome Kiosk Mode + หน้าเว็บโหลดรูปบนมือถือ อยู่ในโปรเจกต์เดียวกัน พัฒนาเร็ว ดูแลง่าย ไม่ต้องติดตั้งโปรแกรมเพิ่ม
  2. Python (OpenCV + FastAPI/WebSocket) + Next.js: หากตู้ใช้กล้องโปร DSLR (Canon/Sony) หรือต้องการรัน Python แยกต่างหากสำหรับกล้อง
  3. Desktop App (Electron / Tauri): รวมทุกอย่างแพ็กเป็นไฟล์ .exe สำหรับรันบน Windows ตู้แบบ Standalone
* **คำตอบที่เลือก**: `1 แต่เปรียบเทียบ next.js กับ go`
* **มติทางวิศวกรรม (ADR-04)**:
  * เลือก Next.js Full-Stack (TypeScript Monorepo) และจัดทำตารางเปรียบเทียบกับ Go อย่างละเอียด
  * กล้องและการประมวลผล Canvas ทำงานบน Web API และ WebGL ได้อย่างเป็นธรรมชาติ

### คำถามที่ 5: สเกลจำนวนผู้เข้าร่วมงานและการคำนวณความจุ (Sizing)
* **คำถาม**: (คำถามสุดท้ายเพื่อเคาะตัวเลข Sizing และ Acceptance Criteria) สเกลจำนวนผู้เข้าร่วมงานที่คาดการณ์ไว้และจำนวนวันจัดงาน อยู่ที่ประมาณเท่าใดครับ?
* **ตัวเลือกที่มีให้เลือก**:
  1. *(Recommended)* งานเปิดบ้าน 2 วัน: คาดการณ์ผู้ถ่าย ~500-1,000 คน/วัน (รวม 1,000-2,000 รูป, ความจุ ~3-5 GB, จัดเก็บ 7 วัน ฟรี 100% บน Cloudflare R2)
  2. งาน 1 วัน: คาดการณ์ผู้ถ่าย ~300-500 คน (รวม ~500 รูป, ความจุ ~1.5 GB, ฟรี 100%)
  3. งานสเกลใหญ่ 2 วัน: ผู้ร่วมงานหนาแน่น ~1,500-2,500 คน/วัน (รวม ~4,000 รูป, ความจุ ~10 GB)
  4. ระบุตัวเลขเฉพาะเจาะจงเอง (แจ้งจำนวนคนและวัน)
* **คำตอบที่เลือก**: `(Recommended) งานเปิดบ้าน 2 วัน: คาดการณ์ผู้ถ่าย ~500-1,000 คน/วัน (รวม 1,000-2,000 รูป, ความจุ ~3-5 GB, จัดเก็บ 7 วัน ฟรี 100% บน Cloudflare R2)`
* **มติทางวิศวกรรม**:
  * คำนวณความจุจัดเก็บภาพรวม 1,000–2,000 รูป (ขนาด 1.5–2.5 MB/รูป) ใช้พื้นที่ประมาณ 3–5 GB
  * อยู่ใน Free Tier ของ Cloudflare R2 (10 GB ฟรี และ Egress 0 บาท) ➜ ต้นทุนคลาวด์ = 0 บาท

### คำถามที่ 6: สื่อส่งมอบภาพถ่าย (Digital-Only vs Physical Print)
* **คำถาม**: [Task 00 - มิติงบประมาณฮาร์ดแวร์ & ประสบการณ์] ตู้ Photo Booth นี้กำหนดให้เป็นแบบ 'ดิจิทัล 100% (สแกนรับไฟล์ผ่าน QR)' หรือ 'มีเครื่องปริ้นต์รูปจริงหน้างานด้วย' ครับ?
* **ตัวเลือกที่มีให้เลือก**:
  1. *(Recommended)* Digital-Only 100% (ประหยัดงบสุด คิวไวสุด): เน้นดาวน์โหลดผ่าน QR Code และแชร์ลง Social Media ได้ทันที ต้นทุนหมึก/กระดาษเป็น 0 บาท
  2. มีเครื่องพิมพ์ภาพถ่ายด่วน (Hybrid Print + QR): มีตู้พริ้นเตอร์ Dye-Sub / Canon Selphy พิมพ์รูปขนาด 4x6 หรือ Photostrip ให้น้องถือกลับบ้าน (มีต้นทุนค่ากระดาษ/หมึกเพิ่ม ~5-10 บาท/รูป)
* **คำตอบที่เลือก**: `(Recommended) Digital-Only 100% (ประหยัดงบสุด คิวไวสุด): เน้นดาวน์โหลดผ่าน QR Code และแชร์ลง Social Media ได้ทันที ต้นทุนหมึก/กระดาษเป็น 0 บาท`
* **มติทางวิศวกรรม (ADR-05)**:
  * ไม่ต้องจัดหาเครื่องพิมพ์ Dye-Sub และไม่ต้องซื้อกระดาษ/หมึกพิมพ์ (งบประมาณ = 0 บาท)
  * ลดเวลาการรอคอยพิมพ์รูป 45–60 วินาที ทำให้ระบายคิวได้รวดเร็วที่สุด

### คำถามที่ 7: รูปแบบภาพถ่าย (Photo Layout Modes) & Reminder Flag
* **คำถาม**: [Task 00 - มิติการจัดวางภาพ & UX Flow] สไตล์ภาพถ่ายที่ตู้จะบันทึกและเรนเดอร์ลงใน Canvas Template จะเป็นรูปแบบใดครับ?
* **ตัวเลือกที่มีให้เลือก**:
  1. *(Recommended)* Photostrip 3-4 ช็อต (สไตล์ตู้สติกเกอร์เกาหลี/Life4Cuts ยอดนิยม): ถ่ายต่อเนื่อง 3-4 แอ็กชันแล้วนำมารวมลงในกรอบเส้นยาวแนวตั้ง เด็กมัธยมชอบมากที่สุด
  2. ถ่ายช็อตเดียวจบ (Single Shot 9:16 / 3:4): ถ่ายท่าเดียวแล้ววางกรอบ มศว ทันที เน้นความกระชับ รวดเร็ว คิวไม่สะดุด (ใช้เวลาไม่เกิน 30 วินาที/คน)
  3. ผู้ใช้เลือกได้ 2 โหมด: หน้าตู้มีปุ่มให้เลือกว่าจะถ่ายแบบ '1 ช็อตด่วน' หรือ '4 ช็อต Photostrip'
* **คำตอบที่เลือก**: `ตอนนี้ให้ได้ 2 โหมดไปก่อน อาจมีการปรับเปลี่ยนแพลนในอนาคต มาร์กไว้ให้ปรับได้ด้วย แต่ถ้าไม่กลับมาปรับให้เตือน`
* **มติทางวิศวกรรม (ADR-06)**:
  * ออกแบบเอนจิน Canvas ให้รองรับ Dual-Mode (Single Shot 4:3 และ Photostrip 3–4 ช็อต)
  * ควบคุมการเปิด-ปิดโหมดผ่าน Configuration Flag
  * บันทึก Reminder Flag ในเอกสารเพื่อแจ้งเตือนให้ทีมสรุปโหมดหลักก่อนเริ่มงาน

### คำถามที่ 8: การคัดกรองท่ามือในงานคนเยอะ (Multi-person & Edge Cases)
* **คำถาม**: [Task 00 - มิติความแม่นยำ AI & Edge Case ในงานคนเยอะ] กรณีมีเพื่อนมายืนถ่ายด้วยกัน 2-3 คน หรือมีคนเดินผ่านฉากหลังในงาน จะให้ระบบ AI กรองการจับท่ามืออย่างไร เพื่อไม่ให้กล้องกดถ่ายเองโดยไม่ตั้งใจ?
* **ตัวเลือกที่มีให้เลือก**:
  1. *(Recommended)* จับมือที่อยู่ใกล้กล้องที่สุด (Largest Hand Area / Depth) + มีปุ่มแตะถ่ายสำรองบนจอ: กรองคนเดินผ่านข้างหลังออก และมีปุ่ม Tap เผื่อกรณีแสงมืดหรือน้องทำท่าไม่ติด คิวจะได้ไม่สะดุด
  2. จับแค่มือแรกที่ตรวจพบ (First Detected Hand): ไม่กรองระยะความลึก ใครยกมือก่อนก็นับถอยหลังทันที (เสี่ยงลั่นถ้าคนเดินผ่านหลัง)
  3. ต้องชูมือพร้อมกัน 2 ข้าง/ทุกคนในเฟรม: ใช้สำหรับยืนยันความพร้อมก่อนกดถ่าย
* **คำตอบที่เลือก**: `(Recommended) จับมือที่อยู่ใกล้กล้องที่สุด (Largest Hand Area / Depth) + มีปุ่มแตะถ่ายสำรองบนจอ: กรองคนเดินผ่านข้างหลังออก และมีปุ่ม Tap เผื่อกรณีแสงมืดหรือน้องทำท่าไม่ติด คิวจะได้ไม่สะดุด`
* **มติทางวิศวกรรม (ADR-07)**:
  * คัดกรองเฉพาะมือที่มี Bounding Box Area ใหญ่ที่สุดและมีค่าแกนลึก z ใกล้กล้องที่สุด
  * ใส่ปุ่มสำรองบนหน้าจอ Viewfinder ให้แตะถ่ายรูปด้วยนิ้วสัมผัสได้ทันที

### คำถามที่ 9: ฮาร์ดแวร์กล้องประจำตู้
* **คำถาม**: [Task 00 - มิติฮาร์ดแวร์กล้องและการติดตั้งหน้างาน] กล้องที่จะนำมาติดตั้งประจำตู้ Photo Booth จะเป็นประเภทใดครับ?
* **ตัวเลือกที่มีให้เลือก**:
  1. *(Recommended)* External USB Webcam 1080p (เช่น Logitech C920/C922/Brio): เสียบ USB ตรงเข้าคอม เสถียรสูงสุด ไม่ร้อน ไม่ดับ ใช้งานต่อเนื่องได้ทั้งวัน รองรับ WebRTC แท้ 100%
  2. ใช้กล้องมือถือต่อเป็นเว็บแคม (ผ่าน DroidCam / Camo): ภาพสวยคมชัดสูง แต่ต้องระวังเครื่องมือถือร้อนและแบตเตอรี่เสื่อมเมื่อเปิดกล้องต่อเนื่อง 6-8 ชม.
  3. กล้อง Webcam ในตัวเครื่อง Laptop: ไม่ต้องใช้อุปกรณ์เพิ่ม แต่ความคมชัดอาจต่ำ (720p) และมุมกล้องมักจะเงยส่องจากด้านล่าง
  4. กล้อง Mirrorless/DSLR (ผ่าน HDMI Cam Link): คุณภาพระดับโปรหน้าชัดหลังเบลอ แต่ต้องมี Capture Card และระบบไฟ DC Coupler เสริม
* **คำตอบที่เลือก**: `(Recommended) External USB Webcam 1080p (เช่น Logitech C920/C922/Brio): เสียบ USB ตรงเข้าคอม เสถียรสูงสุด ไม่ร้อน ไม่ดับ ใช้งานต่อเนื่องได้ทั้งวัน รองรับ WebRTC แท้ 100%`
* **มติทางวิศวกรรม (ADR-08)**:
  * ใช้กล้อง USB Webcam 1080p เสียบตรงเข้าพอร์ต USB รองรับ WebRTC Native ไม่เกิดปัญหาความร้อนสะสมหรือแบตเตอรี่หมด

### คำถามที่ 10: การควบคุมดูแลและแก้ไขปัญหาเฉพาะหน้าของสตาฟ (Staff Admin)
* **คำถาม**: [Task 00 - มิติการควบคุมดูแลและแก้ไขปัญหาเฉพาะหน้าของสตาฟ] เมื่อตู้ค้าง, ผู้ใช้เดินหนีกลางคัน, หรือสตาฟต้องการตรวจเช็กระบบหน้างาน สตาฟควรมีช่องทางควบคุม (Admin / Reset Control) แบบใดครับ?
* **ตัวเลือกที่มีให้เลือก**:
  1. *(Recommended)* Hidden Secret Trigger (เช่น แตะโลโก้ มศว มุมซ้ายบน 5 ครั้ง หรือกด Ctrl+Shift+A): เปิด Staff Modal ลับสำหรับรีเซ็ตหน้าจอ, สลับกล้อง, ดูยอดคนถ่าย, และสั่ง Re-sync รูป โดยไม่ต้องเปิดหน้าต่างใหม่
  2. Staff Web Dashboard แยกต่างหาก (/admin บนมือถือสตาฟ): ควบคุมและดูสถิติผ่านมือถือของสตาฟคนเฝ้าบูท
  3. ปุ่มลัดแป้นพิมพ์อย่างเดียว (เช่น กดปุ่ม 'R' เพื่อรีเซ็ตหน้าจอ, กด 'ESC' เพื่อยกเลิก): เรียบง่ายที่สุด แต่ต้องมีคีย์บอร์ดซ่อนอยู่หลังตู้
* **คำตอบที่เลือก**: `มี 2 แบบ 1 และ 2`
* **มติทางวิศวกรรม (ADR-09)**:
  * On-Kiosk Modal: แตะโลโก้ มศว มุมซ้ายบน 5 ครั้ง (หรือกด Ctrl+Shift+A) เพื่อเปิด Staff Modal ลับสำหรับรีเซ็ตคิว/สลับกล้อง
  * Remote Dashboard: มีหน้าเว็บ `/admin` บนมือถือของสตาฟสำหรับมอนิเตอร์จำนวนผู้ถ่ายรูปและสั่งรีเซ็ตหน้าจอจากระยะไกล

### คำถามที่ 11: การจัดวางจอมอนิเตอร์ทางกายภาพ (Monitor Orientation)
* **คำถาม**: [Task 00 - มิติการจัดวางจอมอนิเตอร์ทางกายภาพ (Monitor Orientation)] จอมอนิเตอร์ที่หันหาผู้ใช้งานหน้าตู้ จะติดตั้งในลักษณะใดครับ?
* **ตัวเลือกที่มีให้เลือก**:
  1. *(Recommended)* จอแนวนอนปกติ (Landscape 16:9) แต่แบ่งฝั่งซ้ายเป็น Viewfinder แนวตั้ง 9:16 และฝั่งขวาเป็นแผงฟิลเตอร์/ข้อมูล: ยืดหยุ่นสูงสุด ใช้มอนิเตอร์ทั่วไปได้เลย ไม่ต้องมีขาตั้งหมุนจอแนวตั้ง
  2. จอแนวตั้งเต็มตัว (Portrait 9:16 หมุนจอ 90 องศา): ให้ความรู้สึกเหมือนตู้สติกเกอร์เกาหลี/มือถือขนาดยักษ์ (ต้องมีขาแขวนหมุนจอ)
  3. Responsive เต็มจออัตโนมัติ: ออกแบบ UI ให้หมุนปรับอัตโนมัติตามการตั้งค่า Orientation ของ Windows Monitor (รองรับทั้งแนวตั้งและแนวนอน)
* **คำตอบที่เลือก**: `จอแนวนอน 16:9 เต็มจอ ส่วนการออกแบบ layout ไว้ทีหลัง`
* **มติทางวิศวกรรม (ADR-10)**:
  * ติดตั้งจอมอนิเตอร์มาตรฐาน 16:9 แนวนอน โดยการจัดวาง Viewfinder และส่วนแสดงผลจะถูกออกแบบใน Task การดีไซน์ Layout (Task 04)
